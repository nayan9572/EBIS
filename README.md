## 🔍 What is EBIS?

EBIS is a **runtime causal intelligence framework** designed to operate continuously on live systems. Instead of building a static causal model, it maintains an evolving set of causal beliefs that are constantly tested against reality.

The system follows a rigorous closed-loop lifecycle:

- Discovers causal relationships from raw telemetry
- Validates them using statistical and physics-based checks
- Accumulates evidence across multiple operating regimes
- Challenges existing beliefs through autonomous experiments
- Tracks trust, freshness, and uncertainty dynamically
- Plans and executes targeted interventions
- Updates or rejects beliefs based on direct runtime feedback

---

## ⚡ What Makes EBIS Different?

Most causal systems stop after discovering relationships. **EBIS goes much further.**

It treats causality as a **living, time-bound process** rather than a fixed graph. The framework integrates:

1. Causal Discovery (DIFC)
2. Statistical & Physics Validation
3. Persistent Belief Memory with Lifecycle States
4. Autonomous Experimentation (AEX)
5. Trust & Freshness Auditing
6. Intervention Planning & Runtime Stabilization

EBIS does not aim for a “final” causal model. It maintains **provisional causal beliefs** whose reliability is continuously re-evaluated against new evidence.

## 🧬 Theoretical Foundation: Causal Entropy Hypothesis (CEH)

EBIS is built on a deeper theoretical foundation called the **Causal Entropy Hypothesis (CEH)**.

CEH proposes that entropy is fundamentally the *realized causal unfolding of energy* within a directed causal graph, rather than a measure of disorder or missing information. This framework provides the mathematical and philosophical basis for several core behaviors in EBIS:

- Why uncertainty (`U`) is irreducible and must be explicitly tracked
- How latent/hidden causal factors continuously inject entropy
- Why causal structures must remain dynamic and subject to revision
- How stable configurations compress and enable higher-level organization

## 🏛️ Runtime Authority Architecture

EBIS follows a strict layered authority model. Each layer has clearly defined responsibilities and constraints:

| Layer | Component | Role | Key Constraint |
|-------|-----------|------|----------------|
| 1 | **CRE** | Reality Generation | Only generates reality; does not decide causality |
| 2 | **Observer** | Runtime Verification | Detects instability, regime shifts, and prediction failures |
| 3 | **DIFC** | Causal Discovery | Owns edge topology and confidence; cannot mutate memory |
| 4 | **PWE + SBL** | Scientific Validation | Refines effects and learns regime behavior |
| 5 | **ORCH** | Orchestrator (Truth Center) | Owns Canonical Truth, Edge Memory, and Sensitivity Store |
| 6 | **Belief Lifecycle** | State Management | VALID → LATENT → CONFLICTING → STALE → UNRELIABLE → REJECTED |
| 7 | **Trust / Freshness / AEX** | Evidence Challenge | Attacks beliefs from multiple directions |
| 8 | **ACIS** | Governance | Consumes truth; does not own it |
| 9 | **EIL** | Intervention Planning | Single authority for stabilization actions |
| 10 | **Theta Hub** | Mutation Authority | The only component allowed to change runtime state |

This separation ensures that **truth, discovery, validation, and action** remain clearly separated and auditable.

## 🧮 Example: Multi-Step Causal Validation

Before any edge is accepted as `[VALID]`, EBIS subjects it to rigorous multi-step verification. Example from a live `burn_duration → ca50` relationship:

- **Step 1**: ElasticNet regression (`R² = 0.987`)
- **Step 2**: Block-bootstrap significance testing
- **Step 3**: Dynamic threshold derivation + outlier rejection
- **Step 4**: Physics consensus check
- **Step 5**: Lifetime evidence tracking across regimes

Only after passing all stages is the edge granted validated status with an associated trust score.

## 🔬 Current Research Focus

EBIS is under active development. Key open challenges include:

- Tight calibration between actuator-level perturbations and variable-level causal effects
- Robust trust estimation combining statistical evidence, regime coverage, and experimental outcomes
- Sustained multi-regime stabilization (e.g., 2000 → 5000 RPM transitions)
- Improved detection and handling of latent (hidden) causal variables
- Dynamic integration of conflicting evidence streams

The Causal Entropy framework provides guiding principles for addressing several of these challenges, particularly around uncertainty and latent pressure.
